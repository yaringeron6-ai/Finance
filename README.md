# מכ"ם פיננסי — Finance Radar (v1)

מעלים מאזן בוחן חודשי של 12–36 חודשים, והמערכת מחזירה רשימת ממצאים ממוינת לפי סכום. כל ממצא מסומן "לבדיקה" ולא כטעות.

## מה המערכת בודקת

**סריקה היסטורית**
- **יתרות שנגררות:** חשבונות מעבר, מקדמות והפרשות שהיתרה בהם לא ירדה מתחת לסכום מסוים במשך 12 חודשים ומעלה.
- **דפוסים חוזרים:** חריגה שמופיעה באותו חודש קלנדרי ברוב השנים.

**התראות על החודשים האחרונים**
- **מגמה:** הוצאה שעולה, או הכנסה שיורדת, 3 חודשים ברציפות ויותר מ-15% מהרמה הרגילה. כולל תחזית מתי תחצה את היעד החודשי.
- **חריגה:** חודש שרחוק מאוד מהחציון של 12 החודשים שלפניו.
- **קשר שנשבר:** שני כרטיסים שזזים יחד, למשל עלות המכר והכנסות, והיחס ביניהם השתנה.

## מבנה

```
radar/
  connectors/   מקורות נתונים: קובץ (פעיל), Priority / חשבשבת / SAP B1 (מתוכננים)
  normalize.py  כל פורמט קלט → טבלה אחידה (ledger)
  classify.py   זיהוי סוג וקבוצת כרטיס לפי שם, כשהקובץ לא מציין
  analysis/     stale, recurring, trends, anomalies, relations
  engine.py     מריץ הכול ומרכיב דוח
  synthetic.py  חברה בדויה עם בעיות שתולות, לדמו ולבדיקות
  web/          אפליקציית FastAPI + ממשק בעברית
```

כדי להוסיף מערכת הנהלת חשבונות, כותבים מחלקה אחת שיורשת מ-`Connector` ומחזירה שורות של מאזן בוחן. המנוע עצמו לא משתנה.

## הרצה

```bash
pip install -e ".[dev]"
uvicorn radar.web.app:app --reload
```

אחר כך פותחים את http://localhost:8000 ולוחצים "הרץ דמו".

```bash
pytest
```

## פורמט הקלט

- **פורמט ארוך:** `כרטיס, שם כרטיס, חודש, חובה, זכות, יתרה`, שורה לכל כרטיס בכל חודש.
- **פורמט רחב:** `כרטיס, שם כרטיס`, ועמודה לכל חודש שמכילה את התנועה נטו.
- **עמודות אופציונליות:** `סוג` (הכנסות, הוצאות, נכס וכו'), `קבוצה` (מעבר, מקדמות, הפרשה, הפרשה שוטפת).
- **קובץ יעדים (אופציונלי):** `כרטיס, יעד חודשי`.

## מגבלות ידועות

- במקדמות עם תחלופה שוטפת, ה"רצפה" של היתרה יכולה לכלול גם פריטים חדשים. לכן הממצא מבקש פירוט לפי ספק.
- כשאין עמודת יתרה, יתרות מאזניות מחושבות מאפס, בלי יתרת פתיחה. המערכת מציגה על כך אזהרה.
- המערכת לא נותנת ייעוץ מס.
